# API Темпа для Flutter и Dart

[Подключение Dart к тестовому HTTP и обзор последних изменений](UPDATE-DART.md).

Баллы, магазин, рейтинг организаторов и украшения описаны в [отдельном обновлении](UPDATE-SHOP.md).

Серии мероприятий, история выпусков и годовой рейтинг описаны в [обновлении API серий](UPDATE-SERIES.md).

API использует HTTPS, JSON и Bearer JWT. Локальный стенд слушает `https://localhost:3443`. Точный адрес зависит от окружения приложения. Базовый префикс всех операций — `/api`.

- [Контракт OpenAPI 3.1](../openapi.json) содержит типы полей для генерации моделей.
- [Swagger UI](https://localhost:3443/docs) позволяет отправить запросы вручную. После входа вставьте токен в **Authorize**.
- Даты событий передавайте в UTC с суффиксом `Z`, например `2026-11-21T15:00:00.000Z`. Афиша показывает время Москвы, UTC+3. Дату рождения передавайте как `YYYY-MM-DD`.
- `id`, `owner`, `event`, `user`, `ticket` — целочисленные идентификаторы. `{id}` в пути относится к сущности в соответствующем разделе.
- `attended`, `banned`, `deleted` возвращаются как `0` или `1`. Место `rank` принимает `1`, `2`, `3` или `null`.
- Клиент берёт токен из ответа на регистрацию или вход. Передавайте `Authorization: Bearer <token>`. JWT действует 2 часа. При `401` очистите локальный токен и предложите войти. Храните JWT в защищённом хранилище устройства.
- На физическом телефоне `localhost` указывает на телефон. Для интеграции используйте доступный телефону адрес с доверенным сертификатом. Локальный Compose по умолчанию доступен только на компьютере и использует самоподписанный сертификат.

## Общие ответы

Успешные операции возвращают `200`. Если операция ничего не возвращает, тело равно `{"ok":true}`. Ошибки имеют вид `{"error":"сообщение"}`. Для ветвления интерфейса используйте HTTP-статус.

| Код | Значение |
| --- | --- |
| `400` | Ошибка JSON, валидации или указанного значения |
| `401` | Нужен действующий токен. При входе означает неверные данные или заблокированный аккаунт |
| `403` | Операция не разрешена роли, владельцу или участнику |
| `404` | Объект или билет отсутствует либо недоступен текущему пользователю |
| `409` | Состояние мешает операции, например запись уже есть, мест нет, событие снято |
| `413` | JSON превышает 32 КиБ |
| `429` | Лимит входа и регистрации по IP. Учитывайте `Retry-After` |
| `500` | Ошибка сервера |

## Аккаунт

### 1. `POST /api/register`

Публичный запрос. Создаёт пользователя с ролью `user` и начинает сеанс.

```json
{"name":"Ваня","email":"vanya@example.org","birth":"2003-04-15","password":"change-me-test-password"}
```

Имя — 2–60 символов, пароль — 10–128. Возвращает `{"token":"<JWT>","id":7,"name":"Ваня","role":"user"}`. При занятой почте возвращает `409`.

### 2. `POST /api/login`

Публичный запрос. Принимает `{"email":"vanya@example.org","password":"change-me-test-password"}`. Возвращает такой же объект сеанса, как регистрация. Роль будет `user` или `admin`. До 40 запросов входа и регистрации суммарно с одного IP за 15 минут.

### 3. `POST /api/logout`

Требует JWT. Тело отсутствует. Отзывает текущие JWT аккаунта на всех устройствах и возвращает `{"ok":true}`. Удалите токен из локального хранилища после выполнения.

### 4. `GET /api/me`

Требует JWT. Возвращает `id`, `name`, `email`, `role`, `birth`, счётчики `attended` и `held`, `xp` и `level`, а также массивы:

- `created` — собственные события, включая заявки на модерации.
- `tickets` — записи пользователя. Каждый билет содержит `id`, `event`, `user`, `token`, `attended`, `rank`, `title`, `start`, `sport`, `duration`, `status`, `gate`. Для PNG используйте `id` билета. `token` связан с проходом на конкретное событие.
- `achievements` — записи `{event,title,kind,rank}`. `kind` принимает `participant` или `podium`. Возвращает пустые массивы, если записей пока нет.

## Афиша и запись

### 5. `GET /api/events`

Публичный список одобренных событий активных организаторов, отсортированный по времени начала. Возвращает массив. Завершённые события входят в ответ. Для экрана «Ближайшие» отбирайте `start > now`. Свободные места — `capacity - booked`.

### 6. `GET /api/events/{id}`

Публичная карточка одобренного события. Для скрытой заявки или снятого события доступ есть у организатора и администратора. Возвращает поля создания, `id`, `owner`, `organizer`, `booked`, `status` и `reviews`. Элементы отзывов имеют поля `name`, `stars`, `body`.

Статусы события — `pending` (ожидает решения), `approved` (одобрено), `rejected` (отклонено), `removed` (снято). Время окончания равно `start + duration` минут.

### 7. `POST /api/events`

Требует JWT. Создаёт заявку пользователя со статусом `pending`. Выберите будущее время. Администратор затем публикует заявку через операцию 16.

```json
{
  "title":"Вечерний забег",
  "sport":"Бег",
  "description":"Разминка и совместный забег на пять километров.",
  "place":"Набережная Дона",
  "lat":47.2138,
  "lng":39.7172,
  "start":"2026-11-21T15:00:00.000Z",
  "duration":60,
  "capacity":20,
  "minAge":16,
  "gate":"qr"
}
```

`sport` принимает название вида спорта от 2 до 60 символов, например `Настольный теннис`. Режимы допуска — `open` (по списку), `ticket` (электронный билет), `qr` (QR-билет). Длительность 5–1440 минут, ёмкость 1–5000 участников, возраст 0–100 лет. Область Ростова-на-Дону ограничена широтой 47.10–47.36 и долготой 39.52–39.92. Ответ — `{"id":42,"status":"pending"}`.

### 8. `POST /api/events/{id}/join`

Требует JWT. Тело отсутствует. Регистрирует участника на будущее одобренное событие. Проверяет возраст на дату события по Москве, свободные места, отсутствие повторной записи и принадлежность события другому организатору. Ответ — `{"event":42}`. Затем запросите `/api/me` и найдите билет по `event == 42`.

### 9. `DELETE /api/events/{id}/join`

Требует JWT. Тело отсутствует. Отменяет запись до начала события. При уже подтверждённом посещении возвращает `409`. После удаления билет исчезает из профиля, а его QR становится недействительным.

### 10. `GET /api/tickets/{id}/qr`

Требует JWT владельца билета. `{id}` — номер из массива `tickets` в `/api/me`. На успехе отдаёт байты `image/png`. QR доступен для действующего билета в режиме `qr`, пока событие не завершилось и посещение не отмечено. При закрытом допуске, чужом, отменённом или уже использованном билете получите `404`.

Во Flutter загрузите PNG HTTP-запросом с Bearer и передайте `response.bodyBytes` в `Image.memory`. Если показываете электронный билет, используйте ID и имя участника из профиля. Для `open` покажите подтверждение записи.

## Организатор

### 11. `GET /api/events/{id}/roster`

Требует JWT организатора события или администратора. Возвращает массив `{id,user,attended,rank,name}`. `id` — номер билета, `user` — номер аккаунта. Для ручной отметки передавайте номер билета.

### 12. `POST /api/events/{id}/checkin`

Требует JWT организатора или администратора. Подтверждает посещение от часа до начала до времени окончания. Для QR передайте строку, которую прочитал сканер. Для допуска по списку или электронному билету передайте ID билета из `roster`.

```json
{"token":"<строка из QR>"}
```

```json
{"ticket":58}
```

Ответ — `{"name":"Ваня"}`. Повторная попытка возвращает `409`. Билет от другого события или заблокированного пользователя возвращает `404`. После успеха обновите `roster`. Подтверждённое посещение даёт 100 XP.

### 13. `POST /api/events/{id}/awards`

Требует JWT организатора или администратора. После окончания одобренного события выдаёт призовое место участнику с подтверждённым посещением. Тело — `{"ticket":58,"rank":1}`. Место должно быть уникальным внутри события. За места 1, 2, 3 начисляется 150, 100, 50 XP соответственно.

### 14. `POST /api/events/{id}/reviews`

Требует JWT участника с подтверждённым посещением. Доступен после окончания одобренного события. Тело — `{"stars":5,"body":"Хорошая тренировка!"}`. Оценка 1–5, текст 5–1500 символов. Один отзыв на пользователя и событие. При повторе вернётся `409`.

## Администрирование

### 15. `GET /api/admin`

Требует JWT с ролью `admin`. Возвращает `events` со всеми статусами, `users` с полями `id,name,email,role,banned,deleted` и до 500 записей `logs`. Запись журнала содержит `id,at,actor,action,ip,target`. `at` — время UTC, `actor` — ID пользователя или `null`, `ip` — адрес соединения. Скрывайте интерфейс админки для обычного пользователя. Доступ проверяется на сервере.

### 16. `POST /api/admin/events/{id}`

Требует JWT администратора. Тело — `{"status":"approved"}`, `{"status":"rejected"}` или `{"status":"removed"}`. Одобрение публикует событие активного организатора. Отклонение и снятие убирают его из публичной выдачи.

### 17. `POST /api/admin/users/{id}`

Требует JWT администратора. `{id}` — идентификатор аккаунта с ролью `user`. Тело — `{"action":"ban"}`, `{"action":"unban"}` или `{"action":"delete"}`. Блокировка отзывает существующие JWT и удаляет неподтверждённые записи пользователя. Разблокировка разрешает новый вход и начинает отсчёт жалоб заново. Удаление обезличивает аккаунт и снимает его события.

## Справочная операция

`GET /api/openapi.json` публично отдаёт полный контракт OpenAPI 3.1. В репозитории хранится та же версия в `openapi.json`.

## Пример для Flutter

Фрагмент использует `package:http` и тип `Uint8List`. `origin` — адрес сервера без завершающего слеша. Для профиля и QR применяйте одну и ту же авторизацию.

```dart
import 'dart:convert';
import 'dart:typed_data';
import 'package:http/http.dart' as http;

Future<String> signIn(
  http.Client client, String origin, String email, String password,
) async {
  final reply = await client.post(
    Uri.parse('$origin/api/login'),
    headers: {'Content-Type': 'application/json'},
    body: jsonEncode({'email': email, 'password': password}),
  );
  final payload = jsonDecode(utf8.decode(reply.bodyBytes)) as Map<String, dynamic>;
  if (reply.statusCode != 200) {
    throw StateError(payload['error'] as String? ?? 'Ошибка входа');
  }
  return payload['token'] as String;
}

Future<Uint8List> loadTicketQr(
  http.Client client, String origin, String token, int ticketId,
) async {
  final reply = await client.get(
    Uri.parse('$origin/api/tickets/$ticketId/qr'),
    headers: {'Authorization': 'Bearer $token'},
  );
  if (reply.statusCode != 200) {
    final error = jsonDecode(utf8.decode(reply.bodyBytes)) as Map<String, dynamic>;
    throw StateError(error['error'] as String? ?? 'Билет недоступен');
  }
  return reply.bodyBytes;
}
```

## Порядок интеграции

1. Участник входит, получает афишу, открывает карточку, записывается и обновляет профиль.
2. Для `qr` приложение запрашивает PNG по ID билета из профиля. Билет открывается на отдельном экране для сканирования.
3. Организатор открывает список участников. Строка от сканера или выбранный номер билета поступает в `checkin`.
4. После окончания участник может отправить отзыв. Организатор присуждает места и обновляет список.
5. Администратор использует свой JWT для модерации событий и пользователей.
