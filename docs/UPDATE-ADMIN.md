# Обновление администрирования

Панель `/admin` содержит сводку, разделы мероприятий, пользователей, отзывов и журнала. Ссылка «Товары и заказы» открывает `/shop/admin`, где можно добавить и отредактировать товары, подготовить заказ к выдаче, выдать его или отменить с возвратом баллов.

Все методы ниже требуют `Authorization: Bearer <token>` с ролью `admin`. Ошибка `401` означает, что нужно войти, `403` означает, что у аккаунта нет нужной роли. Формат ошибок прежний, `{"error":"…"}`. Старый `GET /api/admin` остаётся доступен.

## Сводка и списки

| Метод | Параметры | Результат |
| --- | --- | --- |
| `GET /api/admin/overview` | | `pendingEvents`, `upcomingEvents`, `activeUsers`, `bannedUsers`, `checkIns`, `openOrders`, `lowReviews` |
| `GET /api/admin/events` | `status=pending\|approved\|rejected\|removed`, `when=upcoming`, `q` по названию, спорту, организатору или ID | Мероприятия, включая неопубликованные |
| `GET /api/admin/users` | `state=active\|banned\|deleted\|admin`, `q` по имени, email или ID | `id`, `name`, `email`, `role`, `banned`, `deleted` |
| `GET /api/admin/reviews` | `state=visible\|hidden`, `stars=1\|2\|3\|4\|5\|low`, `q` по автору, мероприятию или тексту | `id`, `event`, `user`, `stars`, `body`, `eventTitle`, `author`, `hidden`, `reason` |
| `GET /api/admin/logs` | `actor` по ID пользователя, `q` по действию, объекту или IP | `id`, `at` в UTC, `actor`, `action`, `ip`, `target` |

Списки возвращают `{"items":[…],"nextBefore":123}`. Передайте `before=123` вместе с прежними фильтрами для следующей страницы. `nextBefore=null` означает конец списка. Размер страницы задаёт `limit` от 1 до 100, по умолчанию 25. Флаги `banned`, `deleted` и `hidden` в списках числовые, `0` или `1`.

## Действия

- `POST /api/admin/events/bulk` принимает `{"ids":[12,13],"status":"approved","reason":"Площадки проверены"}`. Допустимо до 50 ID и статусы `approved`, `rejected`, `removed`. Возвращает `{"updated":2}` с числом изменённых событий. Если один ID отсутствует, сервер вернёт `404` и откатит весь запрос.
- `POST /api/admin/users/{id}/sessions/revoke` завершает все сессии участника. Тело не требуется, ответ `{"ok":true}`. Уже выданные JWT перестают работать. Участник может войти заново.
- `POST /api/admin/users/{id}/points` принимает `{"delta":25,"reason":"Помощь на мероприятии","requestId":"point-reward-2026-001"}`. Для ключа используйте 16–80 символов из `A–Z`, `a–z`, `0–9`, `_` и `-`. `delta` — целое число от −10 000 до 10 000, кроме нуля. Ответ содержит `id` операции и актуальный `balance`. При сетевом повторе отправьте тот же ключ и те же данные. Сервер вернёт прежний ID без повторного начисления. Отрицательный баланс и повтор ключа с другими данными дают `409`. В истории кошелька операция имеет тип `admin_adjustment`.
- `POST /api/admin/reviews/{id}` принимает `{"hidden":true,"reason":"Содержит личные данные"}` и возвращает `{"ok":true}`. Передайте `hidden:false` для восстановления. Скрытые отзывы исчезают из публичной карточки и исключаются из последующих проверок для автоблокировки. Ранее наложенный бан можно снять из раздела «Пользователи».

Причина для массовой модерации, коррекции баллов и модерации отзыва содержит от 3 до 300 символов. Действия записываются в журнал.
