# Обновление для Flutter и Dart — баллы, магазин и профиль

Существующие запросы, JWT и QR-билеты работают по прежнему контракту. Для новых экранов добавлены десять операций. [OpenAPI](../openapi.json) · [Основной справочник API](API.md)

## Что показать в приложении

- В личном кабинете загрузите `GET /api/me` для билетов, опыта и активности, затем `GET /api/wallet` для баллов, покупок и оформления. Опыт определяет уровень. Баллы расходуются в магазине.
- На витрине загрузите `GET /api/shop/products`. Для пользователя со входом также получите баланс из `/api/wallet`. `stock: null` означает цифровое украшение, `stock: 0` — физический товар закончился.
- После покупки показывайте возвращённый баланс и заказ. Цифровой заказ уже доступен для выбора в профиле. Для физического заказа покажите номер, статус и текст инструкции `pickup`.
- На экране профиля используйте `decoration.badge` как подпись значка и `decoration.theme` как ключ палитры. Для чужого профиля берите оформление из `GET /api/people/{id}`.
- На экране организатора отобразите `organizer.rewardedEvents` и `organizer.nextMilestone`. Публичная таблица организаторов доступна без токена.

## Запросы пользователя

| Метод и путь | Доступ | Данные |
| --- | --- | --- |
| `GET /api/shop/products` | Публичный | Опубликованные товары. Поля `id,title,description,kind,price,stock,theme,image` |
| `GET /api/wallet` | JWT | `balance`, последние 50 записей `history`, `orders`, `decoration`, `organizer`. При чтении учитывает новые начисления |
| `POST /api/shop/orders` | JWT | Тело `{product,requestId}`. Возвращает `{order,balance}` |
| `PUT /api/profile/decoration` | JWT | Тело `{badge,theme}`. Оба значения — ID собственных заказов нужного типа или `null`. Возвращает применённое оформление |
| `GET /api/people/{id}` | Публичный | `{id,name,city,badge,theme,level,held,attended}`. `id` — идентификатор пользователя |
| `GET /api/organizers/leaderboard` | Публичный | `{city,totalEvents,organizers:[{id,name,events}]}`. До 30 организаторов по числу подходящих завершённых событий |

Для запросов с JWT передавайте `Authorization: Bearer <token>`. JSON отправляется с `Content-Type: application/json`.

### Покупка и повтор при сбое

```json
{"product":15,"requestId":"e989c9d4-674a-4862-b99e-172386e99883"}
```

Создайте один случайный идентификатор на попытку покупки. Формат — 16–80 латинских букв, цифр, дефисов и подчёркиваний. UUID подходит. После тайм-аута повторите запрос с тем же `requestId` и `product`. Сервер возвращает исходный заказ с текущим статусом и текущим балансом. Для новой осознанной покупки создайте новый идентификатор.

```json
{
  "balance": 25,
  "order": {
    "id": 61,
    "product": 15,
    "title": "Футболка M",
    "kind": "physical",
    "price": 40,
    "theme": "",
    "pickup": "Покажите номер заказа на стойке организатора.",
    "status": "reserved",
    "created": "2026-11-22 09:30:00"
  }
}
```

- `400` — некорректное тело или идентификатор попытки. `401` — нужен новый вход.
- `404` — товар скрыт или отсутствует.
- `409` — закончился остаток, мало баллов, украшение уже куплено или ключ использован для другого товара. Покажите `error` из ответа и обновите витрину с балансом.
- Цена, название и инструкция сохраняются в заказе на момент покупки. Время `created` и `history.at` приходит как строка SQLite в UTC. Для разбора можно заменить пробел на `T` и добавить `Z`.

### Оформление профиля

```json
{"badge":62,"theme":null}
```

Ответ имеет вид `{"badgeOrder":62,"themeOrder":null,"badge":"Первый старт","theme":""}`. Передавайте текущий набор целиком. Значение `null` снимает украшение. Для выбора фильтруйте `wallet.orders` по `kind` и `status == "fulfilled"`. При чужом заказе или неподходящем типе сервер вернёт `403`. Возможные ключи темы — `mint`, `ocean`, `violet`, `amber`. Пустая строка означает стандартную тему.

## Запросы администратора

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/admin/shop` | Все товары, в том числе скрытые. Физические заказы содержат дополнительно `user` и `buyer` |
| `POST /api/admin/shop/products` | Создаёт товар. Возвращает объект товара |
| `PUT /api/admin/shop/products/{id}` | Обновляет полный объект товара. `id` — ID товара. Для физического товара также передайте `expectedStock` из последнего ответа сервера. При изменении остатка вернётся `409`, после которого нужно загрузить товар заново |
| `POST /api/admin/shop/orders/{id}` | Меняет статус физического заказа. `id` — ID заказа. Тело `{status}`. Возвращает заказ |

```json
{
  "title": "Футболка M",
  "description": "Хлопковая футболка, размер M",
  "kind": "physical",
  "price": 40,
  "stock": 5,
  "pickup": "Покажите номер заказа на стойке организатора.",
  "image": "",
  "active": true
}
```

- Типы товаров — `physical`, `badge`, `theme`. Для `physical` обязательны свободный остаток `stock` и инструкция `pickup`. Для `theme` обязателен ключ палитры. Для `badge` названием значка станет `title`.
- `image` — необязательная ссылка HTTPS. `active` в запросе — boolean, в ответе — SQLite-флаг `0` или `1`. Установите `false`, чтобы скрыть товар из витрины.
- Физический заказ переходит `reserved → ready → fulfilled`. Из `reserved` и `ready` можно перейти в `cancelled`. При отмене возвращаются баллы и единица остатка. Повтор запроса с тем же статусом безопасен. Из конечного статуса изменения отклоняются с `409`.
- Для всех запросов раздела нужна роль `admin`. Другой авторизованный пользователь получит `403`.

## Правила начисления

| Событие | Баллы |
| --- | --- |
| Организатор подтвердил приход участника | +10 участнику |
| Одобренное событие завершилось и хотя бы один участник подтверждён | +30 организатору |
| Организатор провёл каждые пять подходящих событий в Ростове-на-Дону | +40 организатору |

Баллы не начисляются повторно за одно участие или событие. История в `wallet` содержит `kind` (`attendance`, `organization`, `city_bonus`, `purchase`, `refund`), `reference`, `delta` и `at`. `reference` содержит ID билета, события или заказа либо номер этапа городского бонуса. При первом обращении обрабатываются и подходящие записи, созданные до обновления. Рейтинг показывает активных организаторов и доступен для Ростова-на-Дону.
