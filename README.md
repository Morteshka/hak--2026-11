# Темп

Тестовый стенд спортивных мероприятий Ростова-на-Дону. API работает на Go 1.26, стандартном `net/http` и SQLite. Тот же процесс обслуживает HTML, JavaScript и Swagger UI. Контейнер приложения содержит Go-бинарник. Node.js используется при установке браузерных библиотек и запуске интеграционных тестов.

## Запуск и вход

```sh
docker compose up -d --build
```

Откройте https://localhost:3443/ для сайта, https://localhost:3443/docs для Swagger UI и https://localhost:3443/api/openapi.json для контракта OpenAPI 3.1. При первом запуске создаётся самоподписанный сертификат для localhost. Браузер покажет, что локальный сертификат не имеет публичной цепочки доверия.

Администратор по умолчанию — `admin@temp.local`. Сгенерированный пароль можно посмотреть на компьютере владельца стенда:

```sh
docker compose exec web cat /app/data/admin-password
```

Чтобы задать свои данные администратора, задайте ADMIN_EMAIL и ADMIN_PASSWORD в окружении Compose до первого создания базы. Откройте /admin после входа. Для испытания двух ролей используйте второй профиль браузера или приватное окно. Публичная регистрация создаёт только роль user. Каждый пользователь может подать мероприятие на модерацию.

Том `temp-data` хранит БД, ключ подписи JWT и локальную пару TLS. Обычные перезапуски и пересборки сохраняют данные. При обновлении с версии на Node.js используйте существующий том. Go читает прежнюю схему SQLite, хеши паролей scrypt и ключ JWT. Для остановки используйте `docker compose stop`.

## Проверка сценария

1. Зарегистрируйтесь как организатор. Создайте мероприятие с началом через несколько минут и длительностью 5 минут, выберите допуск. Время в форме московское. До одобрения заявку видят организатор и администратор.
2. Администратор открывает /admin и одобряет заявку. Карточка появляется в публичной афише и на карте. На новом стенде также есть четыре демонстрационные тренировки. Отзывы изначально пусты.
3. Войдите другим пользователем и выберите в афише событие с пометкой «QR-допуск». Сервер проверяет возраст на дату события, количество мест и повторную запись. QR появится на экране подтверждения, в карточке события и в разделе «Мои билеты» профиля. Его можно открыть на весь экран. Для остальных режимов допуска сайт покажет электронный билет или отметку о записи по списку.
4. В интервале от часа до начала до окончания тренировки откройте карточку как организатор. При QR-допуске отсканируйте код камерой, затем нажмите «Подтвердить приход». При электронном билете сверьте билет с именем и номером в списке, затем нажмите «Пришёл на площадку». При открытом допуске отметьте участника по списку.
5. После окончания организатор присуждает места подтверждённым участникам. Участник может опубликовать один отзыв о конкретном событии. Профиль возвращает достижения, посещения, проведённые мероприятия, уровень и опыт.
6. Администратор может снять событие, заблокировать, разблокировать или удалить аккаунт. Удаление обезличивает профиль и снимает мероприятия с публикации. В журнале фиксируются успешные операции изменения данных с ID пользователя, временем UTC, объектом и адресом соединения. За Docker-прокси это может быть адрес шлюза.

## Контракт для Dart

[Обновление для Dart-разработчика](docs/UPDATE-DART.md) содержит временный HTTP-адрес, настройки Flutter и список последних запросов.

[Справочник для Dart и Flutter](docs/API.md) описывает все запросы, роли, поля, статусы и работу с QR-билетом. Машиночитаемый контракт находится в [openapi.json](openapi.json).

### Баллы и магазин

Магазин доступен на `/shop`, баланс и покупки — в личном кабинете `/profile`. За подтверждённое участие начисляется 10 баллов, за проведённое событие с подтверждённым участником — 30 организатору. Каждые пять таких событий дают организатору бонус в 40 баллов. На `/organizers` публикуется рейтинг Ростова-на-Дону.

Администратор управляет товарами и выдачей на `/shop/admin`. Значки и темы появляются в кабинете сразу после покупки. Для физических товаров администратор задаёт доступный остаток и инструкцию по получению. Отмена до выдачи возвращает баллы и остаток. При `SEED_DEMO=1` в пустой магазин добавляются два цифровых примера. Таблицы магазина создаются при запуске в существующей SQLite.

[Отдельное обновление для Dart](docs/UPDATE-SHOP.md) описывает новые запросы, выдачу товаров, безопасные повторы покупок и оформление профиля.

### Серии мероприятий и рейтинг

В заявке выберите существующую серию или укажите название новой. Из карточки уже опубликованного события организатор также может добавить выпуск в историю серии. Страница серии показывает ближайшие выпуски, историю, номер выпуска и год серии. Рейтинг на `/organizers` сравнивает организаторов и серии за выбранный год или за всё время. [Обновление API для Dart](docs/UPDATE-SERIES.md)

- Базовый путь API — `/api`. Методы, поля запросов, типы ответов и коды ошибок описаны в OpenAPI. Доступны публичные `GET /events` и `GET /events/{id}`. Список содержит также завершённые события, сайт отбирает будущие для афиши.
- `POST /register` и `POST /login` возвращают `token`, `id`, `name`, `role`. Мобильный клиент передаёт `Authorization: Bearer <token>`. Сайт использует HttpOnly SameSite=Strict cookie. Срок JWT — 2 часа. При 401 нужен повторный вход. Выход отзывает текущие сессии аккаунта. Роль и блокировка проверяются на сервере при каждом запросе.
- `POST /events` возвращает ID заявки. `POST /events/{id}/join` регистрирует участника. `GET /me` возвращает профиль, личные билеты и созданные события. `GET /tickets/{id}/qr` отдаёт приватный PNG. Для строгого QR-допуска передайте отсканированное значение в поле `token` метода `POST /events/{id}/checkin`. В остальных режимах используется числовое поле `ticket` со значением ID билета из списка организатора.
- Время начала передаётся строкой ISO 8601 в UTC с суффиксом Z. ID, ограничения и количество мест — целые числа. Координаты — числа. Флаги SQLite в ответах (`attended`, `banned`, `deleted`) имеют значения 0 или 1. Ошибки имеют форму `{"error":"сообщение"}`.
- По умолчанию порт привязан к loopback хоста. Для физического телефона нужен доступный телефону HTTPS-адрес с доверенным сертификатом. На устройстве localhost указывает на само устройство. Задайте PUBLIC_ORIGIN для абсолютных ссылок предпросмотра при размещении на своём домене.

## Правила тестового стенда

Подтверждение посещения даёт 100 XP и достижение участника. Первое, второе и третье места добавляют 150, 100 и 50 XP соответственно. За завершённое одобренное мероприятие организатору учитывается 100 XP. Каждые 300 XP повышают уровень. Баллы вычисляются из фактических записей, поэтому повторный запрос не удваивает награду.

Автоблокировка применяется после отзывов с оценкой 1–2 от трёх разных подтверждённых участников минимум на двух мероприятиях одного организатора. При разблокировке администратором отсчёт жалоб начинается заново. Координаты места при создании проверяются по прямоугольной области вокруг Ростова-на-Дону.

## Яндекс Карты

На /map видны места отфильтрованных событий. В карточке мероприятия есть карта, ссылка на точку и пешеходный маршрут. Без ключа сайт использует виджет Яндекса, а в заявке — редактор точки OpenStreetMap с предпросмотром в Яндекс Картах. Можно нажать на карту, перетащить метку или ввести координаты вручную.

Для выбора места прямо на карте Яндекса укажите браузерный ключ JavaScript API в переменной `YANDEX_MAPS_API_KEY` в файле `.env` рядом с compose.yaml и выполните `docker compose up -d`. В кабинете Яндекса ограничьте ключ доменом стенда. Ключ этого типа виден браузеру. При недоступности загрузчика JS API сайт возвращается к виджету и резервному редактору. Внешние карты требуют подключения к соответствующему сервису. [Подключение JavaScript API](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/dg/concepts/load)

## Автотесты

```sh
docker build --target test -t temp-rostov-test .
docker run --rm temp-rostov-test
```

Тест поднимает Go-бинарник на случайном локальном порту с временной SQLite-базой и проверяет API, включая конкуренцию за последнее место, QR, права и модерацию. Время изменяется только у тестовых записей для проверки отзывов и награждения. Для разработки без Docker выполните `npm ci` и `go run .` из корня проекта.

## Развёртывание на VPS

Для запуска на отдельном VPS с Docker Compose клонируйте репозиторий и задайте в `.env` публичный адрес. Пример для IP-стенда с самоподписанным сертификатом при пустом томе.

```dotenv
PUBLISH_ADDRESS=0.0.0.0
PUBLISH_PORT=443
PUBLIC_ORIGIN=https://45.9.117.195
TLS_PUBLIC_IP=45.9.117.195
ADMIN_EMAIL=admin@temp.local
```

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail 50 web
curl -kfsS https://45.9.117.195/api/openapi.json -o /tmp/temp-openapi.json
```

`TLS_PUBLIC_IP` используется при первом создании самоподписанного сертификата. Для стенда с доверенным сертификатом передайте `TLS_CERT` и `TLS_KEY` в контейнер через локальный Compose override и смонтируйте соответствующие файлы только для чтения. Для Dart задайте `PUBLIC_ORIGIN` с именем хоста, которое покрывает сертификат. `SEED_DEMO=0` отключает первоначальное заполнение афиши демонстрационными событиями.

Для обновления выполните `git pull --ff-only` и `docker compose up -d --build` из того же каталога. Перед обновлением сделайте резервную копию тома при остановленном контейнере и храните её в закрытом месте. В томе содержатся персональные данные и ключи.

### Временный HTTP для отладки

Дополнительный тестовый HTTP-порт запускает тот же процесс и использует тот же том SQLite. По умолчанию Compose публикует его на `http://127.0.0.1:3080` только при подключении файла `compose.http.yaml`:

```sh
docker compose -f compose.yaml -f compose.http.yaml up -d --build
```

Для согласованного публичного теста задайте `PUBLISH_HTTP_ADDRESS=0.0.0.0` и `PUBLISH_HTTP_PORT=80`. Подключайте оба compose-файла при каждом обновлении, пока HTTP нужен. Для его отключения выполните `docker compose -f compose.yaml up -d`. HTTPS и том работают в обоих режимах. Используйте тестовые пароли и данные.
